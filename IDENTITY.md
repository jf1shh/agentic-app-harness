# ICM — Identity

## Purpose

`agentic-app-harness` is a monorepo of six independent, AI-agent-built applications, plus a
deterministic **harness** (`scripts/`) that senses spec/test drift, turns findings into agent
work orders, and gates merges in CI — with no embedded LLM. Every app is held to the same bar:
a spec in `specs/` before code, Zod schemas for every data model, BDD-style Vitest + Playwright +
axe tests, and a green `node scripts/test-app.mjs <AppName>` before any push.

This repo runs the **full** [ICM](https://github.com/ktnCodes/icm-template) layer stack on top of
the existing rulebook — it routes you to the right place, it does not replace `AGENTS.md`:

| Layer | Where | Question |
|---|---|---|
| 0 | `IDENTITY.md` (this file) | "Where am I?" |
| 1 | `CONTEXT.md` | "Where do I go?" |
| 2 | `stages/<stage>/CONTEXT.md` | "What do I do, in this stage of the loop?" |
| 3 | `_config/` | "What rules/terms apply?" |
| 4 | `stages/<stage>/output/` | "Where does this stage's output actually live?" |

Layer 2/4 map onto the one real pipeline this repo already has: the harness's own
Sense → Propose → Act → Verify → Learn loop (`.agents/AGENTS.md` §8) — see `stages/`.

## Rules

- **`.agents/AGENTS.md` is the single source of truth for how to work in this repo.** This ICM
  layer is navigation on top of it, not a substitute — nothing here overrides a rule stated there.
- Every app under `projects/` is independent: its own `package.json`, its own dependency versions
  (deliberate — see the peer-set lessons in `.agents/AGENTS.md` §6), its own `specs/<app>-spec.md`.
- The harness (`scripts/`) is deterministic and LLM-free by design; it senses, an agent acts, CI
  verifies. See `.agents/AGENTS.md` §8 for the full Sense → Propose → Act → Verify → Learn loop.
- Agents never self-merge (`.agents/AGENTS.md` §5/§8) — a PR is opened, a human merges.
